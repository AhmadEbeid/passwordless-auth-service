# Phase 1 Data Model: Auth: Sign Up & Sign In

**Feature**: [spec.md](./spec.md) · **Plan**: [plan.md](./plan.md) · **Date**: 2026-07-20

Field shapes here inform the Go domain types and goose migrations; the **wire contract is generated by Huma** (see [contracts/](./contracts/auth-api.md)). Types are conceptual (Go/SQL), not final DDL. All timed fields derive from the injectable `Clock` (research D3), never wall-clock in logic.

## User Account

| Field | Type | Notes |
|-------|------|-------|
| id | uuid (pk) | |
| role | enum `coach` \| `athlete` | set at creation, **immutable** (FR-002) |
| phone | text, E.164 `+20…` | **unique** (SC-003); verified at creation |
| google_subject | text, nullable, unique-when-present | linked Google identity |
| google_email | text, nullable | |
| preferred_language | enum `ar` \| `en`, default `ar` | consumer app (FR-027) |
| created_at | timestamptz (RFC3339) | |

**Invariants**: phone normalized to `+20` + exactly 10 significant digits (FR-004); the row **exists only after a Verification is confirmed** (FR-010, SC-004); **no password field anywhere** (FR-017).
**Relationships**: 1‑to‑many Sessions; referenced by Admin Audit Events.

## Verification *(the OTP challenge — spec's "Verification Code")*

Carries **pending-signup context** so `confirm` can construct the account (which does not exist yet).

| Field | Type | Notes |
|-------|------|-------|
| id | uuid (pk) | |
| phone | text `+20…` | |
| intent | enum `signup` \| `signin` | drives duplicate vs. no-account checks |
| code_hash + salt | text | hashed 6-digit code (research D2) |
| pending_role | enum, nullable | required for `signup` (FR-001) |
| pending_language | enum `ar`\|`en`, nullable | carried into the new account |
| pending_google_subject / _email | text, nullable | set for the Google-first signup path (US3) |
| sent_at | timestamptz | |
| expires_at | timestamptz | `sent_at + 10 min` (FR-007) |
| failed_attempts | int, default 0 | wrong-code count (FR-008); provider send-failures **not** counted (FR-028) |
| sends_in_window | int | sends counted for the 30-min cap (FR-029) |
| locked_until | timestamptz, nullable | set on 5 failed attempts **or** send-cap exceeded (FR-008/029) |
| status | enum `pending`\|`verified`\|`expired`\|`locked`\|`canceled` | |

**State transitions**:
- `pending` → `verified` (correct code before expiry) → account created (signup) / session issued (both).
- `pending` + wrong code → `failed_attempts++`; 5th → `locked` (`locked_until = now + 30 min`).
- `pending` → `expired` when `now > expires_at`.
- send request → `sends_in_window++`; exceeding the cap → `locked`. Resend allowed only after 60 s (FR-009) and while not locked.

**Notes**: transient; not tied to an account until confirmed. The duplicate-phone check (signup, FR-005) and no-account check (signin, FR-015) happen **before** a Verification/code is created. Lockout is **per-phone**, not per-device (edge case).

## Session *(per-device, revocable)*

| Field | Type | Notes |
|-------|------|-------|
| id | uuid (pk) | |
| account_id | uuid (fk → User Account) | |
| token_hash | text, unique | opaque token hashed at rest (research D1) |
| device_label | text, nullable | per-device identification |
| created_at / last_active_at | timestamptz | |
| expires_at | timestamptz | rolling idle-expiry, extended on activity; **60-day** idle window (research D4, FR-025) |
| revoked_at | timestamptz, nullable | set by sign-out (FR-026) |

**Invariants**: valid **iff** `revoked_at IS NULL AND now < expires_at`; **multiple concurrent rows per account** (per-device, FR-031); sign-out revokes only the current row.
**State**: `active` → (sign-out) `revoked`; `active` → (idle past `expires_at`) `expired`. Either → routes to the entry gate on next launch (FR-020, US4).

## Admin Audit Event *(minimal, append-only)*

| Field | Type | Notes |
|-------|------|-------|
| id | uuid (pk) | |
| actor_admin_id | text/uuid | the authorized admin (admin auth assumed external) |
| action | text | e.g. `clear_lockout` |
| target_account_id | uuid (fk → User Account) | |
| created_at | timestamptz | |
| metadata | jsonb, nullable | |

**Invariants**: **append-only** — no update/delete (Constitution VII); emitted only for actions that change auth state (FR-023). A no-op lockout clear emits **nothing** (edge case).

## Cross-entity invariants

- No account without a confirmed Verification (FR-010, SC-004).
- Exactly one account per phone (SC-003) — enforced by the unique constraint **plus** the pre-send duplicate check (FR-005).
- Every timed rule reads the injectable Clock (research D3), enabling deterministic tests.
